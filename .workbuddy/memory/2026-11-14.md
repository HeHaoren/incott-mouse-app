## 离屏截图自检法（值得复用）

Electron 隐藏窗口 `show:false` **不会重绘**，`capturePage()` 只能拿到首帧（一开始截到的是 DPI 页）。
正确做法：`webPreferences.offscreen: true` + 监听 `paint` 事件存 `NativeImage`，`capturePage()` 为空时回退用它。

- 脚本放临时目录（`%TEMP%\incott-shot\`）：`shot.js`（离屏窗口）+ `mock-preload.js`（假 api）。
- 假 preload 要**照抄真实 `webPreferences`**：`sandbox: false`，否则 preload 无法 `require` 本地 shared 模块，
  报 `module not found: path` 并让整个渲染层崩掉（`window.i18n` 未注入 → `Cannot read properties of undefined`）。
- 设备态靠 mock 的 `getState/openDevice` 返回 `{opened:true, isWireless:true, modelInfo:{...,is8KReceiver:true}}`；
  语言切换要暴露一个 `__fireLangChanged` 触发 `onLangChanged`，才会走真实的 `applyI18n + renderAll` 路径
  （否则只替换 `data-i18n` 节点，JS 动态生成的模式卡仍是旧语言）。
- 跑 electron 前必须 `unset ELECTRON_RUN_AS_NODE`，否则会被当 node 执行、`require('electron')` 直接 MODULE_NOT_FOUND。

## DPI 键指示灯命令实测拿到（0x0A）——用户暂不做进 UI

- 结论链修正两次，别再被 `str_led_*` 误导：那是**接收器模式名**（`off=关闭/neon=仅警告电池/
  breathing=电池状态/flicker=连接状态和回报率/flowwater/ambilight`），中文来自原生驱动 `Language/ch.xml`。
  真正的本体灯是另一组：`str_dpi_led_dx_text=DPI灯效`、`dx1=常亮`、`dx2=呼吸`、`dx3=关闭`。
- **实测命令 0x0A**：发 `09 0A 02 00 00 00 00 00` → DPI 键灯立刻熄灭，0x89 状态不变。故 `0x0A` = 本体灯，
  2 = 关闭；0=常亮、1=呼吸（对应 dx1/dx2，尚未单独验证）。
- 该灯**不可读**：0x8A~0x8D 全是无效回显 `01 09 03 03 00 09 00 00`；命令 4/5 的 sub 6 之后也是无效值
  （要读只能自己记住上次写的值）。
- 静态分析工具链备忘：`pip install capstone pefile` 可用；GamingMouse.exe 未加壳、ImageBase 0x400000、
  IAT 在 0x576000（pefile 的 `imp.address` 已是 VA，**不要再加 ImageBase**）；线性反汇编会错位，
  必须按函数入口对齐。`str_dpi_led_*` 只在 Language/*.xml 里，exe 中搜不到。
- 盲试前用 `backup.js` 存了 `config-backup.json`（可读配置快照）。用户决定"这一 part 不管了"，
  所以 UI 不加三档，只在 docs/protocol.md 3.8b 留档。

## 结论反转：0x0A 是误判，DPI 键灯根本不可设置（同日 13:56）

- 用户想让它"常亮"→ 盲试 `0x0A` 的 0/1/3~8 及复合包（`[0A,0,01]`、`[0A,0,FF,00,00]` 等）**全部点不亮**。
  早前 `[0A,2]` 之后"灯灭了"是误判：这颗灯本来就不常亮，只在切 DPI / 低电量时亮。
- 决定性证据来自**只读旁路抓包**（`watch.js`：一个句柄 90ms 轮询 `getFeatureReport(9)`，
  原生驱动写入会覆盖 Feature 缓冲区 → 能读到别人的报告，无需 USBPcap）：
  官方 v1.3.7 驱动识别到 G24 并完整下发了 `8F → 85 06 00 00 F1 → 82 01/02/03/05（buf[7] 区分 X/Y）→
  83 → 84 01~05 → 85 01/03/02 → 86 00~05 → 88 01`，**全程没有一条灯效命令**，UI 也没有「DPI灯效」入口。
- 结论：G24 固件不提供该灯的设置能力，工具无法让它常亮。文档 3.8b / HANDOFF 待办 1 已按此改写。
- 顺带收获（可考虑补实现）：老驱动用了网页驱动没有的 `0x85 sub 6`（`85 06 00 00 F1 00 00 00`，
  buf[4]=241 传感器 ID），以及 `buf[7]` 作为 X/Y 区分位的写法。
- **教训**：单次"灯灭了"不能当证据，尤其是那种"本来就不常亮"的指示灯；要么抓真实写入，要么多值对照。
