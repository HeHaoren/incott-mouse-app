## 枚举缓存过期：切 8K 后重连失败（已修 578bbc3）
- 现象：有线连接 → 切 8K → 断开 → 重连报 `cannot open device with path ...MI_02&Col01... 0x00000002`（ERROR_FILE_NOT_FOUND）。
- 根因：切 8K/有线无线模式会让设备重新枚举，接口 path 全变；`deviceCache` 永不失效，重连仍拿旧 path 开设备。
- 修复：缓存 10s TTL + `invalidateCache()`；`openDevice` 改 async，缓存路径全失败时强制重新枚举重试一次；`mouse:close` 清缓存；渲染层错误提示去掉 IPC 包装前缀。

## 拔出鼠标导致主进程未捕获异常（已修 d4bfbe3）
- 现象：拔鼠标弹 "A JavaScript error occurred in the main process: could not read from HID device: hid_read_timeout/GetOverlappedResult (0x48F)"。
- 根因：加了 Input Report 的 `data` 监听后 node-hid 持续后台读设备，拔出瞬间读线程 `emit('error')`，没挂监听 → 主进程未捕获异常。
- 修复：`MouseDevice` 挂底层 error 监听并暴露 `onError/isOpen`；main `handleDeviceGone` 统一清理（关句柄/清缓存/托盘复位/`device:disconnected` 通知）；`withDevice` 包装 exec/read/apply/uploadMacro；`process.on('uncaughtException')` 兜底只拦 HID 断连类；渲染层回未连接 + 中英文提示。
- **教训：Electron 主进程绝不能对 HID 设备只加 data 监听而不加 error 监听。**

## 重连后残留「鼠标已断开」提示（已修 2be6eca / b8fcd47）
- 根因有两层：① 断开 toast 3s 生命周期，快速重连时仍在屏上（连接成功时 `hideToast()`）；② **style.css 没有全局 `.hidden { display:none }`**，只有 `.spinner.hidden` 等组件专属规则，`.toast.hidden` 匹配不到 → toast 永不消失。
- 修复：连接成功清 toast；`handleDeviceGone(err, sourceDevice)` 增加来源实例判定（旧句柄迟到错误不误清新连接），先置空 device 再 close 防重入；toast 改 opacity/transform 过渡（0.14s 淡入淡出，显示 2s，退场后 160ms 再 display:none）。

## 灯效页：接收器指示灯落地 + 本体 RGB 结论（提交 57f79e6）
- 逆向结论：官方网页驱动设备层（chunk-v1013 的 CBAccess）**没有任何鼠标本体 RGB 命令**，只有 setReceiverLED（命令 8）。Colour 页的 apiSaveColourSolution 属于键盘产品（提示语 save_keyboard_success），与本鼠标无关。
- 本体 RGB 确实存在：老原生驱动有 CLedSetDlg + str_led_off/neon/breathing/flicker/flowwater/ambilight 六种模式，但 evidence 里只有 strings dump、没有二进制；要拿命令字必须 USB 抓包（USBPcap/Wireshark）或反汇编原生驱动。
- 命令 8 三档（index 0/1/2 对应 UI 三个按钮，来自 receiverLEDClick 的 1DEL/2DEL/3DEL 绑定）：0 回报率指示、1 电量指示、2 仅低电量警告；回读 0x88 buf[1]。
- 实现：protocol LED_MODE_TABLE + 取值校验；灯效页三档卡（非 8K 置灰提示）、连接时回读、apply 时写入、本地配置/.ict 带 receiverLed；测试 32 全绿。
- 逆向小技巧：bundle 里字符串是 \uXXXX 转义 + 'xxx'.split('').reverse().join('') 反转，先解码再搜关键词。
