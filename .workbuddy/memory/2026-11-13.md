## 自研自绘安装器（23:10–23:35）

用户试过 NSIS 版后说「没有 Filee 的安装向导美观」，确认走自研路线（接受 84MB → 126MB 的体积代价）。

### 架构
- `installer/` 是**独立的小 Electron app**（自己的 package.json + electron-builder.yml），
  用 `npx electron-builder --projectDir installer --config electron-builder.yml` 打包，
  `--config` 路径是相对 projectDir 解析的（写成 `installer/xxx.yml` 会变成 installer/installer/xxx.yml）。
- 载荷 = `dist/win-unpacked`（270 文件 / 273.9 MB），由 `installer/sync-payload.js` 覆盖式同步，
  打完由 `installer/collect.js` 把 portable exe 收进 `dist/`。
  输出必须走 `dist/setup-build`，**不能直接用 `dist`**，否则和应用的 `dist/win-unpacked` 互相覆盖。
- 打包目标 `portable`（自解压单文件），配 `splashImage` 做解包时的品牌闪屏；
  成品 126.2 MB（NSIS 84 MB）。
- 安装：复制载荷 → PowerShell WScript.Shell 建快捷方式 → `reg add` 写 HKCU 卸载项 → 写
  `.incott-install.json` 标记（用于识别旧版本、允许覆盖升级）。
- 卸载：`UninstallString` 指向主程序 `--uninstall`；主进程 `runUninstall()` 先弹确认，
  `taskkill /FI "PID ne <self>"` 关掉其它实例，删快捷方式+注册表，再用
  `cmd /c ping -n 4 127.0.0.1 >nul & rmdir /s /q "<dir>"` 等自己退出后删目录。

### 踩的坑（都是环境/Electron 特有，值得记）
1. **Electron 的 fs 会劫持 `.asar`**：`fs.copyFileSync('...app.asar', ...)` 报
   `ENOENT, not found in ...app.asar`——Electron 把 asar 当目录。必须 `require('original-fs')`。
2. **`app.getPath('localAppData')` 不存在**：Electron 没有这个 path 名，用 `process.env.LOCALAPPDATA`。
3. **安全沙箱把 reg.exe / powershell.exe / wmic.exe 拉黑**，且 `execFile` 遇到黑名单会**同步抛错**，
   不是回错误给 callback。所有外部程序调用都得包一层 `execFileSafe`（try/catch + resolve err），
   并且把「注册表/快捷方式失败」降级成警告文案，不能让它中断整个安装。
4. **环境的批量删除保护**：一次删 >50 个文件会被 `safe-delete` 拦下（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`），
   所以 sync-payload 改成覆盖式增量同步；`dist-setup/`、`dist-setup2/` 也因此删不掉，留给用户手动清理。
5. **构建前必须关掉所有 electron 进程**，否则 `dist/setup-build/.../app.asar` 被占用，
   electron-builder 在 remove 阶段报 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`（错误信息藏在 Go 栈里）。

### 验证情况
- 安装流程实测（装到临时目录）：270/270 文件 sha1 与 `dist/win-unpacked` 完全一致（只少 app.asar 之外我们剔除的 app-update.yml）。
- 四态界面（选项/进度/完成/出错）均 CDP 截图确认；便携版解包后能正确读到 `resources/payload`。
- **未实测**：快捷方式创建、注册表写入、`--uninstall` 卸载（沙箱拦了 reg/powershell，只验证了降级路径）。
